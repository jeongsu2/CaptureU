# 스파이크: Instagram Graph API로 무엇을 받을 수 있나 (2026-11-28)

개발 전에 실제 계정으로 API를 호출해서 확인한 결과다. 테스트 계정과 참고 계정의 아이디, 개별 수치는 공개 저장소라서 적지 않는다.

## 설정

- 로그인 방식: **Unified Login** (비즈니스용 Facebook 로그인 기반, 인스타 계정으로 로그인 가능, 페이스북 페이지 불필요)
  - 새로 만든 앱은 "Instagram 로그인 API 설정"을 쓸 수 없다고 대시보드에 안내된다.
- 구성 권한: `instagram_basic`, `instagram_manage_insights`, `instagram_manage_comments`, `instagram_manage_messages`(이용 사례의 필수 권한이라 뺄 수 없음)
- 토큰: 시스템 사용자 액세스 토큰(SUAT), 호스트 `graph.facebook.com`, 응답 버전 v27.0
- 확인 스크립트: [scripts/ig_probe.sh](../scripts/ig_probe.sh)

## 확인된 것

| 항목 | 결과 |
|---|---|
| 내 계정 정보, 게시물 목록 | ✅ |
| 릴스 인사이트: views, reach, saved, shares, total_interactions, ig_reels_avg_watch_time, reels_skip_rate | ✅ 전부 |
| 댓글 본문 | ✅ |
| 팔로워 연령·성별, 참여자 연령 | ✅ 계정 단위만 |
| 참고 계정 Business Discovery | ✅ Unified Login에서 동작 |
| 참고 계정 릴스의 view_count | ✅ 팔로워 약 8만, 14만 규모 계정 모두 옴 |
| 좋아요를 숨긴 계정의 like_count | ❌ 필드 자체가 빠짐 |
| 개인 계정을 참고 계정으로 조회 | ❌ `code 110 / subcode 2207013 "Invalid user id"` |

## 설계에 반영할 것

1. **비교 기준은 조회수 중앙값 배수.** 좋아요는 숨길 수 있어서 보조 지표로만 쓴다.
2. **게시 직후 지표는 빠르게 바뀐다.** 게시 약 1일 된 릴스의 조회수가 약 20분 사이에 31% 늘었다. 누적값끼리 비교하면 새 게시물이 불리하다.
   - 그래서 **같은 나이끼리 비교**한다 (예: 게시 24시간 시점의 조회수 vs 평소 게시물들의 24시간 시점 조회수 중앙값).
   - API는 현재 누적값만 주므로, **게시물 나이에 따라 수집 주기를 다르게** 해서 직접 곡선을 쌓는다.
3. **댓글 수가 반응의 질을 말해 주지 않는 게시물이 있다.** 댓글 이벤트 게시물은 이모지 한 개짜리 댓글이 대부분이다. 댓글 반응률을 쓰려면 이런 댓글을 거른다.
4. **성별은 대부분 '알 수 없음(U)'이다.** 리포트에서 성별을 크게 보여 주지 않는다.
5. **응답의 `paging.next` URL에 access_token이 그대로 들어 있다.** 외부 API 응답을 로그에 남기기 전에 토큰을 가려야 한다. (스파이크 중 실제로 토큰이 출력에 노출되어 해지했다.)
6. **재시도하면 안 되는 에러가 있다.** 사용자가 비즈니스 설정에서 앱 연결을 끊으면 모든 호출이 `code 190 / subcode 464`로 실패한다. 이 에러는 재시도하지 않고 연결 상태를 '끊김'으로 바꾼 뒤 재연결을 안내한다.

## 토큰 해지 방법

- business.facebook.com에 **페이스북 계정으로** 로그인 → 설정 → 통합 → **연결된 앱** → 앱 삭제
- 대시보드에서 만든 토큰의 시스템 사용자는 "시스템 사용자" 목록에 보이지 않는다.
- 인스타 계정으로 로그인하면 비즈니스 설정에 들어갈 수 없다.

## 아직 확인할 것

- 내 게시물과 참고 계정 게시물의 `caption`, `thumbnail_url`, `media_url`을 받을 수 있는지 (서비스의 핵심 재료)
- 없는 아이디, 비공개 프로페셔널 계정을 조회할 때의 에러
- 호출 한도 응답 헤더 (`X-Business-Use-Case-Usage` 등)
